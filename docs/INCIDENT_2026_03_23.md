# Incident Report — 2026-03-23: Accidental Library Wipe

## What happened

During an attempt to clean dead entries (tracks with missing files) from Music.app,
a script inadvertently deleted every valid track from the library index. No music
files were deleted from disk. The library was restored from a Time Machine / local backup.

---

## Root cause

Two AppleScript bugs, both caused by the same misunderstanding:

### Bug 1 — `exists POSIX file p` inside a `tell application` block

```applescript
tell application "Music"
    ...
    if not (exists POSIX file p) then   -- BUG: dispatched to Music.app
        delete aTrack
    end if
end tell
```

Inside a `tell application "Music"` block, **every unqualified command is dispatched
to Music.app**, not to the OS. Music.app does not implement `exists` for POSIX files,
so it returned `false` for every track — causing every track with a valid file to
be deleted.

The diagnostic that preceded this script appeared to count only a handful of dead entries, but
that script used `do shell script "test -f ..."` inside the tell block — the same
problem: `do shell script` was sent to Music.app, failed silently, and was caught by
`try`, so all shell-based dead checks were quietly ignored.

### Bug 2 — `as string` inside a `tell application` block (discovered earlier)

```applescript
tell application "Music"
    repeat with aPath in pathList
        set aPath to aPath as string   -- BUG: Music.app type coercion
```

`as string` inside a tell block is coerced by Music.app's type system, not
AppleScript's native `text` type. The resulting value does not compare equal to a
plain text string, so all path comparisons silently failed (0 matches). Fix: use
`as text` and pre-process path strings **outside** the tell block.

---

## Rules for future AppleScript inside `tell application "Music"`

| What you want | Wrong (inside tell block) | Correct |
|---|---|---|
| Check file exists | `exists POSIX file p` | Pre-check in Python before calling AppleScript |
| Coerce list item to string | `set s to item as string` | Do `as text` outside the tell block |
| Run a shell command | `do shell script "..."` | Do it in Python / outside the tell block |
| Compare paths | `if p is aPath` (where aPath came from `as string`) | Use `as text` outside the tell block |

**General rule:** Any operation that is not a Music.app property access or track
manipulation should happen **outside** the `tell application "Music"` block.

---

## Safe pattern for dead-entry removal

Pre-filter in Python, then pass only the confirmed-missing paths to AppleScript:

```python
# Python side — safe, uses the OS directly
dead_paths = []
for path in all_track_paths:
    if not Path(path).exists():
        dead_paths.append(path)

# AppleScript side — only receives paths we already know are missing
# Just remove tracks matching those paths, no file-existence check needed
```

The AppleScript then only needs to match paths against the pre-filtered list — the
same single-pass iteration pattern already in `remove_library.py`.

---

## Recovery

Files on disk were never touched — only the Music.app library index was affected.
The library was restored by replacing the active `Music Library.musiclibrary` with an
earlier copy from Time Machine (Music.app also keeps older copies in
`~/Music/Music/Previous Libraries.localized/`).

After a restore like this, any tracks that were archived from disk *after* the backup
was taken will reappear in Music.app as missing. Re-run `remove_library.py` with the
`tracks_to_remove_*.txt` file from that archive run to clear them; paths no longer on
disk are reported as "not found" and skipped safely.
